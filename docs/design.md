# 周期判定与恢复合同

## 事实与职责

插件只决定关联 Key 的周预算何时清零，不创建 Key、不改金额上限、路由或宿主原生窗口
一个 Key 关联一个账号，一个账号可关联多个 Key，各 Key 独立计费与处理
只使用主动刷新得到的唯一 `codex:604800s`、604800 秒窗口及非空观测时间、重置时间
缓存只展示，使用率下降不参与判定，旧样本与缺失窗口不触发清零
新增关联只建立基线；暂停后恢复重新建立基线，不补做历史周期

## 判定

Rref 为已确认结束时间，Tprev 为上一有效观测时间，T 和 R 为新观测及结束时间
W 为 7 天，S=R−W 为新窗口起点，容差 τ 为 2 分钟

| 条件 | 行为 |
| --- | --- |
| T≤Tprev | 保留基线，退避重查 |
| abs(R−Rref)≤τ | 同周期，只更新观测时间，不移动已确认结束时间 |
| R>Rref+τ 且 min(Tprev,Rref)−τ≤S≤T+τ | 确认新周期 |
| 新周期且 S≥Rref−τ | 正常换周，自动清零 |
| 新周期且 S<Rref−τ | 提前重置，默认自动；关闭开关时仅更新周期基线，不清零 |
| 其他边界变化 | 标记异常，不自动清零 |
| 目标窗口缺失、空结束时间、刷新失败 | 保留基线，有界退避 |

到点后上游仍返回旧窗口不视为换周，漏过多个周期只处理当前周期
账号通常每 5 分钟检查一次，maintenance 每轮处理有限账号和待重置 Key
多个 Key 共用账号刷新，持续无法刷新超过 1 小时显示异常

首次确认正常换周或提前重置后，仍立即按设置自动清零一次。完成的关联进入持久的“等待周期固定”阶段；只要结束时间仍随观测时间后移，就不为同一次变化再次清零，也不追加“提前重置”事件。新建关联、暂停后恢复遇到此类窗口时只等待固定，不补清零。
等待阶段仅由有效主动刷新推进：新结束时间不再接近观测时间加 7 天，连续两次有效观测至少间隔 5 分钟，结束时间保持固定（毫秒时间戳变化不超过 1 秒），才将当次窗口确认为基线；候选继续移动则重新计时。完成后恢复正常周期识别，不补做清零。下一完整周周期已越过上次结束时间时，仍可独立按正常换周处理。
旧状态缺少等待阶段字段时保守进入等待，不重放旧清零；无法确认的迁移期间周期可能被跳过。上游未提供周期身份，同一段未固定期内的真实再次重置若与时间漂移无法区分，合并为同一周期，不重复清零。

## 清零与恢复

读取预算快照 → 用精确状态版本保存重置意图 → 调用一次 weekly 清零 → 保存完成
私有状态写入与预算清零不是同一事务，不能假定跨操作原子性
任何未完成意图都视为结果未知，包括意图落盘后进程退出、清零响应丢失、完成落盘失败
结果未知停止自动重试，读回预算只作辅助展示，不能据此证明成功

结果未知保留现有用量并停止自动重试；不提供人工二次清零入口，以免删除期间新增的消费
正常失败在调用清零前发生时仍可重试；多个 Key 独立处理，已完成和结果未知的 Key 不会自动重复
排队样本超过 5 分钟时取消该次排队并重新检查当前周期，停机恢复不直接补做旧样本的清零
管理操作与维护串行，状态版本比较防止过期页面或并发进程重复领取
每个关联保留最近 10 条事件，记录时间、原因和必要错误分类，不记录原始上游错误正文
首次清零成功时每个 Key 记录一次原因与处理时间；内部等待、候选更新、周期固定及页面刷新不追加或改写该事件。真实失败与未知结果继续按原规则记录。

## 页面与设置

主列表参照宿主「使用统计」拆分密钥名称、账号、订阅、平台/类型四列，继续显示本周用量、账号使用百分比、账号预计重置和状态。订阅取自宿主账号目录的 `plan_type`，沿用主项目的 AccountPlanBadge 配色和字号，缺失时显示「—」，不自行推断；平台/类型参照宿主使用统计页面，分别显示 Provider 与认证方式图标，悬停显示文字说明；账号仅展示邮箱，缺少邮箱时展示账号 ID，不附加账户描述。金额显示两位小数；列表不再提供关联详情弹窗。Key 自身的周用量重置时间由宿主独立管理。

每行操作区提供“启用/禁用”和“删除”图标按钮，删除需要弹窗二次确认、无需复选框：前者仅切换关联暂停状态，重新启用会主动刷新并重建基线，不影响宿主 Key；后者经明确确认后删除关联，不删除宿主 Key。移除人工处理弹窗；异常状态仅提示风险，内部保存原有错误/未知结果，不自动重试或清零。

提前重置复选框位于关联列表工具栏，勾选后立刻提交并保存；关闭后提前换周只更新基线、保持正常状态，正常换周仍自动处理。保存使用状态版本检查，不重置基线、不触发清零，也不清除待确认或未知结果。

页面日期直接按浏览器本地时间显示，不显示时区标识，也不在插件状态中保存时区字段。

## 已知限制

清零同时关闭宿主周窗口，下次使用时按上海当天零点加 7 天重新开启
Key 可能比账号窗口提前约 24 小时自然清零一次，插件不改变原生到期时间
上游可能直到首次使用后才给出新周期；插件等待有效样本，不发模型请求制造窗口
提前重置与边界校正在事实层面不能完全区分，所以保留提前清零自动开关，异常时保守停止自动处理
停用或卸载停止未来动作，不能撤销已完成清零

判定边界由 `tests/cycles.rs` 固定，持久化失败、部分失败和并发恢复由 `tests/recovery.rs` 固定
这些逻辑测试不能替代真实宿主联调
