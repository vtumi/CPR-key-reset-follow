# v0.2.3

## 更新

- 密钥清零成功并保存后，按账号和周期调用一次宿主连接测试，再刷新额度，帮助上游固定新周期。多个关联密钥共享一次激活，漂移窗口不重复调用。
- 激活任务随清零完成状态落盘；发送前保存领取状态，失败或结果未知不自动重发。尚未发送的任务可在重启后恢复，样本超过 5 分钟则跳过。
- 删除提前重置开关及全局、按密钥设置字段。识别到有效提前重置后始终自动跟随，不迁移旧开关设置；未知结果与异常边界仍保守停止自动处理。
- 删除界面格式、文案和主题细节测试；保留排序、分页、批量操作、周期判定及重置恢复等业务测试。
- 保留 vtumi 版本的列表、批量删除、创建时间排序、主题前缀和新旧样本保护。修复前端锁文件中错放的依赖快照。

## 兼容与升级

- 要求官方 CPR **≥3.41.2**；SDK 与打包 CLI 固定官方提交 `ba3baddbda7293d1d76ea066dd5e42298618c15a`。仍使用 RPC v7、Management v2、Maintenance v1，不设置版本上限；无上限不表示已验证未来版本。
- 插件标识保持 `tumi.key-reset-follow`，作者为 `tumi`。在原实例更新，保留关联、暂停状态、周期基线及未知结果保护。旧提前重置开关不再控制行为，升级前请确认接受自动跟随。
- 连接测试使用宿主账号模型目录的首个模型，会产生真实上游请求并可能消耗额度，不修改密钥路由或宿主原生重置时间。
- 从 `ming321.key-reset-follow` 切换仍属于独立安装：先停用旧插件，不迁移旧实例状态，不让两个插件同时处理相同密钥。

## 验证

本地通过 Rust 1.99.1 格式检查、严格 Clippy、35 项测试，以及前端 lint、10 项业务测试、类型检查与生产构建。前端使用 Node 24.22.1、现有 pnpm 11.25.0；标签工作流使用仓库指定的 pnpm 12.6.0 独立检查。

不进行界面细节测试。真实 CPR 宿主安装、升级状态保留及真实上游连接测试尚未联调；单元测试、构建和 CI 不能替代该验证。本次发布不执行生产部署。

Linux x86_64、ARM64 安装包及 SHA-256 校验文件通过手动标签工作流构建并上传，产物以该次 CI 实际结果为准。
