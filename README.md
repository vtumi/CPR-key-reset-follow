# 跟随重置

[Codex Proxy RS](https://github.com/zyycn/codex-proxy-rs) 的独立插件，适合固定使用某个 Codex 账号的密钥。关联后，插件会跟随账号的周额度窗口，自动重置密钥的本周用量，减少管理员逐个手动重置的维护负担。

一个账号可以关联多个密钥，各密钥独立计费。正常换周自动处理；上游提前重置或使用重置卡后，可选择自动跟随；关闭提前重置自动清零时，插件直接跳过该次清零并更新周期基线。

## 安装

要求 **官方 Codex Proxy RS ≥3.33.0 · Linux x86_64 / ARM64**，不设置宿主版本上限；宿主仍须支持 RPC v7、Management v2、Maintenance v1。SDK 与打包工具固定官方 [v3.33.0](https://github.com/zyycn/codex-proxy-rs/releases/tag/v3.33.0) 提交 `8c8618aa0f841638262262e3338c115bc075f125`；低于 CPR 3.33.0 需继续使用相应旧插件。无版本上限不代表已验证所有未来版本，CI 通过也不代表已完成真实宿主安装联调。

插件标识为 **`tumi.key-reset-follow`**，作者为 `tumi`。

**从旧标识切换：** `ming321.key-reset-follow` 与当前插件是两个独立插件，不能通过旧插件的版本切换直接更新。先停用旧插件，再从安装入口确认安装新插件；配置完整时宿主可能在安装后自动启用。旧实例的关联、设置、暂停状态、周期基线和“结果未知”保护不会自动转入新实例，即使状态命名空间同为 `follow` 也不共享数据。需要参考旧记录时保留已停用的旧实例，并在新插件中按需重新建立关联、核对提前重置开关；新关联只建立基线，不补做历史清零。不要让两个插件同时处理同一批密钥。

1. 打开宿主的 **插件管理 → 安装插件 → GitHub**。
2. 仓库填写 `vtumi/CPR-key-reset-follow`。版本标签留空即可查询最新正式版，无需勾选“允许查询预发行版”。
3. 点击“下一步”，选择与宿主架构对应的 `.tar.gz` 附件（x86_64 或 aarch64/ARM64），按提示完成安装并启用。
4. 打开插件页面，点击“添加关联”，选择密钥和对应的 Codex 账号。

首次关联只记录当前周期，不清零。密钥应已通过宿主的分组与路由设置使用该账号；插件不会替你调整路由。

安装包和同名 `.sha256` 校验文件见 [Releases](https://github.com/vtumi/CPR-key-reset-follow/releases)。也可以下载后在“上传包”中安装。

**同一插件标识的预发行版更新：** 打开插件详情，选择“手动安装版本”→ GitHub，清空旧的 beta 标签并取消“允许查询预发行版”，按提示保存来源、选择最新正式版并更新。这样后续“检查更新”会查询稳定版；保留旧标签则仍会查询固定的 beta。同一实例内的关联、暂停状态、待处理记录和提前重置开关会保留，不需要删除插件或重新添加关联。

## 使用

列表依次显示密钥名称、账号、状态、订阅、平台/类型等字段，参照宿主 API 密钥页面提供名称/账号搜索、名称/账号/重置时间/状态排序，以及底部筛选结果总数和分页栏（默认每页 20 条）。搜索匹配密钥名称和账号名称、邮箱或 ID，不区分大小写；排序表头依次切换升序、降序和默认顺序，窄屏通过排序选择框操作。状态升序为正常、异常、禁用，未显示的重置时间始终排在末尾。搜索、排序及每页条数变更回到第一页；删除或刷新后自动收敛到有效页。

身份信息按密钥名称、账号、订阅、平台/类型分别展示，同时显示「本周额度」「重置时间」和当前状态；重置时间来自插件保存的关联密钥周期基线，禁用、异常或预计时间失效时统一显示「-」，不直接显示账号最新预计时间。订阅来源为宿主返回的账号资料，缺失时展示「—」。顶部不再提供刷新按钮；页面保持自动更新，读取失败时可通过错误提示重试，后台仍按周期主动刷新额度窗口。重置时间以浏览器本地时区显示为 `YYYY-MM-DD HH:mm:ss`，使用原有普通文字样式。

列表新增「提前重置」列，每个密钥独立使用 iOS 风格开关：开启时该密钥自动跟随账号提前重置清零周用量；关闭时该密钥只更新周期基线、不清零，正常换周仍自动处理。切换立即保存，不影响其他关联密钥。旧关联保留升级前的全局设置作为初始值，首次独立切换后按密钥保存。日期按主项目使用的浏览器本地时间显示，不附加时区标识。

状态只显示「正常」「异常」「禁用」：异常表示窗口数据异常、清零结果未知或持续刷新失败，不会自动补做高风险清零。每行“操作”通过图标提供“启用/禁用”和“删除”，删除关联会弹窗二次确认，无需额外勾选。这里的启用/禁用只影响本插件的关联监测，不改变宿主密钥的启用状态；重新启用时会建立新基线，不补做停用期间错过的重置。

## 使用前了解

- 账号重置后，上游可能要等到下一次使用才返回固定的新周期。插件通常每 5 分钟检查一次；首次确认换周或提前重置时自动清零一次，之后等待新周期结束时间固定，不因未使用期间预计时间持续后移而重复清零或重复记录事件。
- CPR 仍独立计算密钥自身的周用量重置时间，可能比账号窗口早约 24 小时清零。插件不会让这两个时间完全对齐；该时间由宿主独立管理。
- 如果清零结果无法确认，插件会停止自动重试。插件会保留当前用量并停止自动重试，以免误清零新产生的消费。
- 同一插件实例的旧状态无法确认当前周期是否已处理时，先等待有效样本建立稳定基线，不补做可能已完成的清零；这期间无法证实的一次重置可能被跳过。该恢复规则不会读取其他插件实例的状态。
- 停用或卸载可停止后续动作，已完成的清零无法撤销。
