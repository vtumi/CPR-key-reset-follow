# Key 周额度跟随账号重置

[Codex Proxy RS](https://github.com/zyycn/codex-proxy-rs) 的独立插件，适合固定使用某个 Codex 账号的 Key。关联后，插件会跟随账号的周额度窗口，自动重置 Key 的本周用量，减少管理员逐个手动重置的维护负担。

一个账号可以关联多个 Key，各 Key 独立计费。正常换周自动处理；上游提前重置或使用重置卡后，可选择自动跟随；关闭提前重置自动清零时，插件直接跳过该次清零并更新周期基线。

## 安装

要求 **官方 Codex Proxy RS ≥3.18.3 且 <4.0.0 · Linux x86_64 / ARM64**。已在 v3.18.3 验证；允许后续 3.x 正式版安装，不代表这些版本均已验证。

1. 打开宿主的 **插件管理 → 安装插件 → GitHub**。
2. 仓库填写 `Ming-321/CPR-key-reset-follow`。版本标签留空即可查询最新正式版，无需勾选“允许查询预发行版”。
3. 点击“下一步”，选择与宿主架构对应的 `.tar.gz` 附件（x86_64 或 aarch64/ARM64），按提示完成安装并启用。
4. 打开插件页面，点击“添加关联”，选择现有 Key 和对应的 Codex 账号。

首次关联只记录当前周期，不清零。Key 应已通过宿主的分组与路由设置使用该账号；插件不会替你调整路由。

安装包和同名 `.sha256` 校验文件见 [Releases](https://github.com/Ming-321/CPR-key-reset-follow/releases)。也可以下载后在“上传包”中安装。

**从 beta 更新：** 打开插件详情，选择“手动安装版本”→ GitHub，清空旧的 beta 标签并取消“允许查询预发行版”，按提示保存来源、选择最新正式版并更新。这样后续“检查更新”会查询稳定版；保留旧标签则仍会查询固定的 beta。原有关联、暂停状态、待处理记录和提前重置开关会保留，不需要删除插件或重新添加关联。

## 使用

列表按密钥名称、账号、订阅、平台/类型分别展示身份信息，同时显示 Key 的本周用量、账号使用百分比、预计重置时间和当前状态。订阅来源为宿主返回的账号资料，缺失时展示「—」。右上角“刷新列表”更新列表，行内“立即刷新”会主动检查账号额度。

列表顶部提供标注“提前重置”的滑动开关，开启时自动清零提前重置的周用量，关闭时不清零；切换后立即保存。关闭后上游提前重置不清零、无需手动处理，正常换周仍自动处理。日期按主项目使用的浏览器本地时间显示，不附加时区标识。

状态只显示「正常」「异常」「禁用」：异常表示窗口数据异常、清零结果未知或持续刷新失败，不会自动补做高风险清零。每行“操作”通过图标提供“启用/禁用”和“删除”，删除关联会弹窗二次确认，无需额外勾选。这里的启用/禁用只影响本插件的关联监测，不改变宿主 Key 的启用状态；重新启用时会建立新基线，不补做停用期间错过的重置。

## 使用前了解

- 账号重置后，上游可能要等到下一次使用才返回固定的新周期。插件通常每 5 分钟检查一次；首次确认换周或提前重置时自动清零一次，之后等待新周期结束时间固定，不因未使用期间预计时间持续后移而重复清零或重复记录事件。
- CPR 仍独立计算 Key 自身的周用量重置时间，可能比账号窗口早约 24 小时清零。插件不会让这两个时间完全对齐；该时间由宿主独立管理。
- 如果清零结果无法确认，插件会停止自动重试。插件会保留当前用量并停止自动重试，以免误清零新产生的消费。
- 从 v0.1.1 升级时，原有关联、设置与待处理状态保留。旧状态无法确认当前周期是否已处理时，先等待有效样本建立稳定基线，不补做可能已完成的清零；这期间无法证实的一次重置可能被跳过。
- 停用或卸载可停止后续动作，已完成的清零无法撤销。
