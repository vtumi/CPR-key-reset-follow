# 跟随重置

[Codex Proxy RS](https://github.com/zyycn/codex-proxy-rs) 的独立插件，自动跟随关联账号的周额度窗口重置密钥本周用量，支持正常换周和提前重置。一个账号可关联多个密钥，各密钥独立处理。

## 安装与升级

要求 **官方 Codex Proxy RS ≥3.41.2 · Linux x86_64 / ARM64**，宿主须支持 RPC v7、Management v2、Maintenance v1；不设置版本上限不代表已验证所有未来版本。

1. 打开宿主的 **插件管理 → 安装插件 → GitHub**。
2. 仓库填写 `vtumi/CPR-key-reset-follow`，版本标签留空，查询最新正式版。
3. 选择对应架构的安装包，完成安装并启用。
4. 打开插件页面，点击“添加关联”，选择密钥和 Codex 账号。

安装包及 SHA-256 校验文件见 [Releases](https://github.com/vtumi/CPR-key-reset-follow/releases)，也支持下载后上传安装。密钥应通过宿主分组与路由使用关联账号，插件不调整路由。

当前插件标识为 `tumi.key-reset-follow`。同一实例升级会保留关联、暂停状态和周期记录；从预发行版更新正式版时，清空固定标签并取消“允许查询预发行版”。

从 `ming321.key-reset-follow` 切换时，先停用旧插件，再安装当前插件并重新建立关联。两个标识的数据互不共享，不会自动迁移，也不要同时处理同一批密钥。

## 使用

列表支持名称和账号搜索、排序、分页及批量删除，显示本周额度、预计重置时间和状态。页面自动更新，后台通常每 5 分钟主动检查账号额度。时间按浏览器本地时区显示。

- **正常 / 异常 / 禁用**：异常包括窗口异常、清零结果未知或持续刷新失败。
- **启用 / 禁用**：只切换关联监测，不改变宿主密钥状态；重新启用只建立新基线，不补做停用期间的重置。
- **删除**：确认后删除插件关联，不删除宿主密钥或账号。批量删除遇错停止，不自动重试。

## 使用前了解

- 新建关联只记录当前周期，不清零；正常换周和提前重置始终自动跟随。
- 上游可能在下一次使用后才给出固定周期。插件清零一次后等待有效样本确认窗口固定，不因预计时间持续后移重复清零，也不发送模型请求激活额度。
- 清零不可撤销。结果未知时停止自动重试，停用或卸载只能停止后续动作。
- 宿主独立计算密钥周用量的重置时间，可能比账号窗口早约 24 小时，插件不能让两者完全对齐。
- 旧状态无法确认周期是否处理过时，保守等待新基线，可能跳过无法证实的一次重置；旧版激活任务不会继续执行。
